### 1.2 Initialisation order (critical), env file and leak check

`[VERIFIED: src]` The `AIService` constructor in @firebase/ai 3.1.0 captures `app-check-internal` and `auth-internal` **once**, through `getImmediate({ optional: true })`. Both components are registered EXPLICIT, so they only exist after `initializeAppCheck()` and `getAuth()` have run. If `getAI()` runs first, AI requests carry **no** `X-Firebase-AppCheck` and no `Authorization: Firebase <idToken>` header, and enforced App Check rejects them.

**Required order:** `initializeApp` → (debug flag, DEV only) → `initializeAppCheck` → `getAuth` → `getAI`. The full module is ARCH §15.1; minimal form:

```ts
// [UNVERIFIED: our composition; each call VERIFIED (tsc/docs/src)]
declare global { var FIREBASE_APPCHECK_DEBUG_TOKEN: boolean | string | undefined; } // not in public typings [VERIFIED: src]
export const app = getApps()[0] ?? initializeApp(firebaseConfig);          // web config is not secret; commit it
if (import.meta.env.DEV) self.FIREBASE_APPCHECK_DEBUG_TOKEN = import.meta.env.VITE_APPCHECK_DEBUG_TOKEN || true; // BEFORE initializeAppCheck
export const appCheck = initializeAppCheck(app, { provider: new ReCaptchaEnterpriseProvider(SITE_KEY),
                                                  isTokenAutoRefreshEnabled: true }); // default FALSE [VERIFIED: docs]
export const auth = getAuth(app);
export const ai = getAI(app, { backend: new GoogleAIBackend() });
```

- Keep these as **module-level singletons**. React 19 StrictMode and Vite HMR re-run code, and a second `getAI()` with different options throws `already-initialized`.
- **Env file.** Vite 8.3.8 loads `.env`, `.env.local`, `.env.[mode]` and `.env.[mode].local`, in that order `[VERIFIED: src vite getEnvFilesForMode]`. `.env.local` is therefore loaded by `vite build` as well.
  - Put the debug token in **`web/.env.development.local`**, which is loaded only in `vite`/dev mode and is gitignored by the `*.local` rule. RUNBOOK §1.7b uses this file.
  - `vite build --mode e2e` loads `.env.e2e` and `.env.e2e.local`, never `.env.development.local`.
- **Leak check after every build.** Vite inlines **values**, not variable names, so grep for the token value:
  ```bash
  T=$(sed -n 's/^VITE_APPCHECK_DEBUG_TOKEN=//p' web/.env.development.local); [ -n "$T" ] && { grep -rlF "$T" web/dist && echo LEAK || echo "dist clean"; }
  grep -rlF "VITE_APPCHECK_DEBUG_TOKEN" web/dist && echo LEAK || echo "env name absent"   # never grep FIREBASE_APPCHECK_DEBUG_TOKEN: @firebase/app-check 0.13.2 reads that global itself, so it is always in dist (SPEC AC-365) [VERIFIED: src]
  ```
- `import.meta.env.DEV` is false under `vite preview`. A production build served on localhost has **no debug token**, and reCAPTCHA rejects localhost, because localhost is never in the key's domains. Test production builds on a Hosting preview channel instead (U-46; RUNBOOK §4.7).

### 1.3 `getGenerativeModel`: the two shapes

`getGenerativeModel(ai, modelParams: ModelParams | HybridParams, requestOptions?: RequestOptions)` `[VERIFIED: src]`

**ModelParams** (no `mode`): `{ model, systemInstruction?, tools?, generationConfig?, … }`.
- Always runs in the cloud. No Chrome adapter is created, and `response.inferenceSource` is `'in_cloud'`.
- `chromeAdapterFactory` returns an adapter only when `LanguageModel && mode` `[VERIFIED: src]`.

**HybridParams:** `{ mode: InferenceMode; onDeviceParams?: OnDeviceParams; inCloudParams?: ModelParams }`.
- When `mode` is set, **every other top-level key (`model`, `tools`, `generationConfig`, `systemInstruction`) is ignored**, with only a `logger.warn` `[VERIFIED: src]`.
- If `inCloudParams` is omitted, it becomes `{ model: 'gemini-3.5-flash-lite' }` (`DEFAULT_HYBRID_IN_CLOUD_MODEL`).
- A missing model name throws `no-model`.

**OnDeviceParams** = `{ createOptions?: LanguageModelCreateOptions; promptOptions?: LanguageModelPromptOptions }` `[VERIFIED: src d.ts]`.
- `LanguageModelCreateOptions` (extends `LanguageModelCreateCoreOptions`):
  - `expectedInputs?: { type: 'text'|'image'|'audio'; languages?: string[] }[]`
  - `expectedOutputs?` (same shape)
  - `monitor?`
  - `signal?`
  - `initialPrompts?: { role: 'system'|'user'|'assistant'; content: { type, value }[] }[]`
- Defaults when you don't override them: inputs = text(en) + image; outputs = text(en).
- `LanguageModelPromptOptions` = `{ responseConstraint?: object }`.
- The Firebase types have **no** temperature, topK or `samplingMode` for the device. Whether a cast `samplingMode` reaches Chrome is U-06.

**Enum values:**
- `InferenceMode` = `{ PREFER_ON_DEVICE: 'prefer_on_device', ONLY_ON_DEVICE: 'only_on_device', ONLY_IN_CLOUD: 'only_in_cloud', PREFER_IN_CLOUD: 'prefer_in_cloud' }`.
- `InferenceSource` = `{ ON_DEVICE: 'on_device', IN_CLOUD: 'in_cloud' }`. The values are lowercase, so always compare against the constants.

### 1.4 How each mode actually routes

`[VERIFIED: src]` (`callCloudOrDevice`, `ChromeAdapterImpl.isAvailable`, `isOnDeviceRequest`, `chromeAdapterFactory`)

| Situation | ONLY_ON_DEVICE | PREFER_ON_DEVICE | PREFER_IN_CLOUD | ONLY_IN_CLOUD |
|---|---|---|---|---|
| No `LanguageModel` global (Safari, Firefox, all iOS browsers, mobile Chrome, old Chrome, workers, Node) | **cloud, silently** (no adapter; `inferenceSource:'in_cloud'`); `initializeDeviceModel()` is a no-op | cloud | cloud | cloud |
| `availability(createOptions)` = `'unavailable'` | throws `AIError` code `'api-not-enabled'` | cloud | cloud | cloud |
| `'downloadable'` / `'downloading'` | awaits the download promise started by `initializeDeviceModel()`. **If none was started, the promise is `null` and the SDK goes straight to the device call** (a download needs a user gesture; expect an error, U-52) | cloud | cloud | cloud |
| `'available'` | device | device, **unless** the request has a `functionResponse` part, is empty, or has an `inlineData` MIME other than `image/jpeg`/`image/png` (then cloud) | cloud; device only when the cloud throws `fetch-error`, `error` or `api-not-enabled` | cloud |

- `PREFER_ON_DEVICE` **does not check `tools`**. A request with `googleSearch` can run on Nano with no search at all. Never put tools in a PREFER model.
- The `'unsupported'` throw ("Inference mode is ONLY_ON_DEVICE, but an on-device model is not available.") exists in the code but is practically unreachable given the branches above. Handle both `'api-not-enabled'` and `'unsupported'` anyway.
- `[CONFLICT]` ONLY_ON_DEVICE with webp: the docs say it throws; the code skips the MIME check on that path and decodes with `createImageBitmap`. Moot for us, because we only ever send JPEG (U-07).

```ts
// SDK-facts sketch only [UNVERIFIED: this sketch is not compiled]. The canonical, [compiled] module is ARCH §9.5: availabilityNow(io) (= nanoState), deviceReadyNow(io) (= deviceOnlyAllowed) and the UI-only uiCapabilities() 30 s cache.
// The SDK itself calls LanguageModel.availability(onDeviceParams.createOptions) [VERIFIED: src],
// so check with the SAME createOptions object you pass to the model.
export type NanoState = 'no-api' | 'unavailable' | 'downloadable' | 'downloading' | 'available';
export async function nanoState(createOptions: object): Promise<NanoState> {
  const LM = (globalThis as { LanguageModel?: { availability(o: object): Promise<NanoState> } }).LanguageModel;
  if (!LM) return 'no-api';
  try { return await LM.availability(createOptions); } catch { return 'unavailable'; }
}
export const deviceOnlyAllowed = async (createOptions: object) => (await nanoState(createOptions)) === 'available';
```

- **No caching for gate decisions.** Inside the gate, call `deviceReadyNow(io)` / `availabilityNow(io)` (ARCH §9.5; `deviceOnlyAllowed` / `nanoState` above) immediately before each S0/S1 call, and for every other device-readiness decision the gate makes (SPEC D-03, AC-007). A cache of up to 30 s exists only in `uiCapabilities()` for the capability panel, the header chip and the HUD Policy tab; the gate never reads it. Per-call latency of `availability()` is U-60.
- Checking `inferenceSource` after the call is **too late** for S0/S1, because the data has already left. Still assert `=== InferenceSource.ON_DEVICE` afterwards as a tripwire (SPEC AC-022). The fetch-level tripwire is §1.17.
- `inferenceSource` is **always** set on responses and stream chunks, and defaults to `'in_cloud'` (`createEnhancedContentResponse(response, inferenceSource = IN_CLOUD)`) `[VERIFIED: src]`. The HUD maps `'on_device'` → `ON_DEVICE` and `'in_cloud'` → `IN_CLOUD`. Rule-based paths log `RULES_ONLY` themselves.
- Hackathon rule: all app AI inference must go through Firebase AI Logic. `LanguageModel.availability()` is fine in the capability module. **Never call `LanguageModel.create()` or `prompt()` directly for features** (§8).

### 1.6 `initializeDeviceModel`, the capability panel and session behaviour

- **Signature:** `model.initializeDeviceModel(onDownloadProgress?: (progress: number) => void): Promise<void>`, with progress from 0 to 1 `[VERIFIED: src d.ts]`.
- It calls `LanguageModel.availability(createOptions)`. If the model is downloadable, it calls `LanguageModel.create({...createOptions, monitor})`, which reports `downloadprogress` → `e.loaded`.
- It **must run inside or after a user gesture** (a click handler); a download without one throws `[VERIFIED: docs]`.
- It is a no-op for ONLY_IN_CLOUD or when there is no adapter. The SDK exposes **no** availability method; use `availabilityNow()` (ARCH §9.5; `nanoState()` in §1.5).
- Internals, firebase 13.4.0 `ChromeAdapterImpl` (T-061) `[VERIFIED: src]`:
  - `downloadIfAvailable` awaits `availability(createOptions)` and starts `create({...createOptions, monitor})` for `downloadable` **and** `downloading` (a create during Chrome's own download attaches to it). There is one await before `create()`, so the click's transient activation must survive it.
  - The session that `create()` resolves to is **never destroyed**: the SDK keeps only the promise, so the model stays resident. `ai/capabilities.ts`'s direct path destroys it at once (D-87).
  - Your `monitor` in `createOptions` wins over `onDownloadProgress`. `initializeDeviceModel` throws `API_NOT_ENABLED` for `unavailable` only in ONLY_ON_DEVICE mode.
  - The constructor writes default `expectedInputs`/`expectedOutputs` into `createOptions` only when they are missing, so a deep-frozen, fully specified object is safe (D-86).
  - With ONLY_ON_DEVICE and `downloadable`/`downloading`, `isAvailable` awaits `downloadPromise` (null unless `initializeDeviceModel` ran) and returns true; the call then creates a session, which can itself trigger the download. That is one more reason the gate pre-checks `availability()` and never calls the SDK unless the answer is `available`.
- **Each on-device call creates a new `LanguageModel` session and destroys the previous one** `[VERIFIED: src]`. Consequences:
  - single-turn only;
  - `initialPrompts` are re-processed on every call;
  - no chat on the device.
- `countTokens` does not work on the device: it throws `request-error`, and ONLY_ON_DEVICE throws `[VERIFIED: src]`.
- **Device input limit: 9,216 tokens** `[VERIFIED: docs]`.
- AI Monitoring in the console shows **no** on-device calls `[VERIFIED: docs]`, so the in-app Ledger is the evidence.

Day-1 DevTools check (spike c, U-01). Run it on a top-level page; it is not available in workers:

### 1.7 Structured output: device and cloud are configured separately

`[VERIFIED: docs+src]` https://firebase.google.com/docs/ai-logic/hybrid/web/generate-structured-output

- **Device:** `onDeviceParams.promptOptions.responseConstraint`, a JSON Schema object.
- **Cloud:** `inCloudParams.generationConfig` with `responseMimeType: 'application/json'` (or `'text/x.enum'`) **plus exactly one of**:
  - `responseSchema` (a `Schema` helper or a `SchemaRequest`), or
  - `responseJsonSchema`, typed `{ [key: string]: unknown }` `[VERIFIED: src d.ts]`; it requires `application/json`.
  - The SDK throws if both are set, or if a schema is set without a matching MIME type.
- **Our rule (D-04):** one **plain JSON Schema object** per prompt, kept in `shared/prompts/`, used both as `responseConstraint` (device) and as `responseJsonSchema` (cloud). ARCH §9.3's `plain()` helper (`JSON.parse(JSON.stringify(s))`) produces it.
- **`Schema` helper gotchas:**
  - every property is **required** unless listed in `optionalProperties`, the opposite of JSON Schema;
  - on `GoogleAIBackend`, `format` may only be `'enum'` or `'date-time'`;
  - `SchemaShared` keys: anyOf, description, enum, example, format, items, maxItems, minItems, maximum, minimum, nullable, properties, propertyOrdering, title.
- U-04: does Chrome accept a Firebase `Schema` **instance** as `responseConstraint`? The instance's own keys are `{type, properties, optionalProperties, nullable}`, and only `toJSON` produces `required`. Also unverified: which keywords Chrome enforces, and whether it tolerates `nullable:false`. Plain objects avoid the question.
- **Gemini cloud JSON-Schema support** `[VERIFIED: docs]` (https://aistudio.google.com/docs/structured-output):

  | Keyword | Status |
  |---|---|
  | enum, minItems/maxItems, required, additionalProperties, `["string","null"]` | enforced |
  | minLength/maxLength, min/maxProperties, uniqueItems, contains | not enforced |
  | minimum/maximum | enforcement not stated |

  - Very large or deeply nested schemas get 400 INVALID_ARGUMENT. Seen Nov 20: `maxItems` on arrays of objects alone triggers `400 "too many states for serving"` (U-45, D-73).
  - Output is **valid** JSON, not necessarily **correct** JSON, so always validate the values.

```ts
// [VERIFIED: tsc --strict]  hybrid + image + both schemas
const model = getGenerativeModel(ai, {
  mode: InferenceMode.PREFER_ON_DEVICE,
  onDeviceParams: {
    createOptions: { expectedInputs: [{ type: 'text', languages: ['en'] }, { type: 'image' }],
                     expectedOutputs: [{ type: 'text', languages: ['en'] }] },
    promptOptions: { responseConstraint: cueSchema },            // ON-DEVICE schema (prefer a plain object; U-04)
  },
  inCloudParams: {
    model: 'gemini-3.5-flash-lite',
    systemInstruction: 'You are concise.',                        // CLOUD ONLY
    generationConfig: { responseMimeType: 'application/json', responseSchema: cueSchema, maxOutputTokens: 1024,
                        thinkingConfig: { thinkingLevel: ThinkingLevel.LOW } },
  },
});
const imagePart: InlineDataPart = { type: 'inlineData', inlineData: { data: base64NoPrefix, mimeType: 'image/jpeg' } };
```

**Convention:** put the full instructions **in the first text part of the user turn**, so the device and the cloud get identical instructions. Cloud `systemInstruction` is optional extra. `initialPrompts` with role `system` compiles, but its runtime effect is U-44, so don't rely on it (ARCH §9.3's `explainModel` uses it; keep the instructions in the user turn too).

### 1.8 Parts and images

- **In v13 every part literal needs `type`** (`'text'` | `'inlineData'`). Without it the build fails with TS2322 "Property 'type' is missing" `[VERIFIED: tsc]`. At runtime the SDK would fill it in (`assignPartType`).
  - Plain strings are accepted inside the array: `generateContent(['prompt', imagePart])`.
  - `[CONFLICT]` Snippets in the gemini-geo-safety and compliance reports use `{ inlineData: {...} }` without `type`, which is wrong for TS in v13.
- `inlineData.data` is base64 **without** the `data:…;base64,` prefix.
- **MIME types:** device `image/jpeg` and `image/png` only (`SUPPORTED_MIME_TYPES`); cloud png, jpeg, webp (AI Studio also lists heic and heif). **Always send our re-encoded JPEG.**
- **Limits** `[VERIFIED: docs]`:
  - 20 MB per request in total; base64 makes the payload larger; an oversized request gets 413;
  - images above 3072×3072 are scaled down and padded;
  - tokens: an image of 384 px or less on both sides costs 258; larger images are tiled into 768×768 tiles at 258 each;
  - `mediaResolution` is **not** a field of `firebase/ai`'s GenerationConfig `[VERIFIED: src]`.
- **Order:** AI Studio's tip is text **before** the image for one image plus text; the Firebase samples use `[prompt, imagePart]` `[VERIFIED: docs]`. Quality difference: U-14.

### 1.9 Streaming, abort and timeouts

```ts
// [VERIFIED: tsc]
const { stream, response } = await model.generateContentStream(parts, { signal: ctrl.signal, timeout: 60_000 });
for await (const chunk of stream) { append(chunk.text()); badge(chunk.inferenceSource); }
const final = await response;   // GenerateContentStreamResult.response is a Promise
```

- Streaming works on the device (the SDK wraps `promptStreaming`) and in the cloud.
- **Timeouts:** `RequestOptions.timeout` (ms) can be set in `getGenerativeModel(…, requestOptions)` or per call via `SingleRequestOptions` (which adds `signal`). The default is 180000 ms. It is implemented with an internal `AbortController` combined with the caller's signal through `AbortSignal.any` `[VERIFIED: src]`.
  - **It only covers the wait for the response headers.** `makeRequest` clears the timer in a `finally` as soon as `fetch()` resolves, so neither reading a non-streamed body nor a stream's chunks is bounded by it (the SDK's own comment: a stream that starts at 300 ms and ends at 5,000 ms is not aborted by a 3,000 ms timeout). The model-level `requestOptions` are spread into each call's `SingleRequestOptions`, so the same holds for a timeout set in `getGenerativeModel` `[VERIFIED: src 13.4.0, T-065 review]`. The gate therefore needs its own deadline (an `AbortSignal` passed per call, aborted on its own timer) to bound pass A's stream and every body read (TASKS T-062).
  - `generateContentStream` resolves only after the **first chunk** has arrived (`processStream` → `processStreamInternal` awaits one `reader.read()` before returning) `[VERIFIED: src @firebase/ai 3.1.0, T-062]`. The gate's deadline therefore races the call itself, every `next()` of the stream and the aggregated `response` (`ai/egressGate.ts`).
- `signal` and `timeout` abort **only the cloud fetch**; they are not passed to the device. Aborting does not stop billing `[VERIFIED: src]`. For device timeouts use `Promise.race`; the next device call destroys the old session (§1.6).
- When streaming, the SDK's aggregated `groundingMetadata` is **overwritten by every chunk, including with `undefined`**. Capture it inside the loop (§1.13).
- U-05: Chrome 157's `promptStreaming` chunks may be deltas (the SDK assumes deltas) or cumulative.

### 1.10 Errors, blocks and refusals

`[VERIFIED: src]`

- `AIErrorCode` values: `error`, `request-error`, `response-error`, `fetch-error`, `session-closed`, `invalid-content`, `api-not-enabled`, `already-initialized`, `invalid-schema`, `no-api-key`, `no-app-id`, `no-model`, `no-project-id`, `parse-failed`, `unsupported`.
- `e.code` is the bare string; `e.message` looks like `"AI: … (AI/unsupported)"`.
- **Cloud HTTP errors** (429, 400, 403, App Check rejection) throw `fetch-error` with `customErrorData.status`.
- **A `fetch()` that throws** (offline, DNS, the fetch tripwire's `TripwireError`) is re-thrown by `makeRequest` as `AIError` code `error` with the message `Error fetching from <url>: <original message>`; only an `AbortError` passes through unwrapped (a `DOMException`). So the gate reads the tripwire's `tripwire:<REASON>` text in the message and `tripwire.lastTrip()`, never the error type `[VERIFIED: src 3.1.0 makeRequest, T-062]`.
- **`api-not-enabled` has two sources:** the device (`availability()` = `'unavailable'` on ONLY_ON_DEVICE) and the cloud (HTTP 403 `SERVICE_DISABLED`, with `customErrorData.status`). `ai/errors.ts` tells them apart by the status `[VERIFIED: src 3.1.0, T-062]`.
- **`response.text()` throws `response-error`:**
  - when `finishReason` is RECITATION, SAFETY, BLOCKLIST, PROHIBITED_CONTENT, **SPII**, MALFORMED_FUNCTION_CALL, LANGUAGE, UNEXPECTED_TOOL_CALL, TOO_MANY_TOOL_CALLS, MISSING_THOUGHT_SIGNATURE, MALFORMED_RESPONSE, or any IMAGE_* value;
  - when `promptFeedback.blockReason` is SAFETY, OTHER, BLOCKLIST or PROHIBITED_CONTENT.
- **`MAX_TOKENS` (value `'MAX_TOKENS'`) does NOT throw.** You get truncated text, so treat a JSON parse failure as a failure.


### 1.17 How the SDK issues requests (facts for the fetch tripwire, ARCH AD-05/§8.5)

`[VERIFIED: src @firebase/ai 3.1.0 index.esm.js]`

- **Cloud calls** build `fetchOptions = { method: 'POST', headers: await getHeaders(url), signal: combinedSignal, body }` and call the **global** `fetch(url.toString(), fetchOptions)` at request time.
  - So a wrapper on `globalThis.fetch`, installed before the first AI call, sees every cloud request.
  - The URL is a string on `https://firebasevertexai.googleapis.com`.
- **Body** is `JSON.stringify(cleanedParams)`:
  - `contents[].parts[]` carry `text` or `inlineData`;
  - a string `systemInstruction` is wrapped as `{ role: 'system', parts: [{ type: 'text', text }] }`, and `type` is stripped for the wire, so the wire shape is `systemInstruction.parts[].text`;
  - scan only text parts. Base64 image data is never string-scanned (false hits).
- **Headers are awaited before `fetch`** (App Check token, Auth ID token). Two calls started together may reach `fetch` in either order.
- **Device calls** never fetch `firebasevertexai`. The Chrome adapter decodes `inlineData` images with `fetch('data:<mime>;base64,…')`, so **a fetch wrapper must pass `data:` URLs through untouched**.
- **Install order** `[VERIFIED: docs (ECMAScript module semantics)]`:
  - `import` declarations are hoisted. A module's dependencies are evaluated, in the order of its import statements, **before** its own body. "First statement of `main.tsx`" therefore runs after `App` and `firebase/init` have been evaluated.
  - Install the tripwire from a side-effect module imported **first**: `import './ai/tripwire-install';` as line 1 of `main.tsx` (file `web/src/ai/tripwire-install.ts`, ARCH §3.1, §8.5). That module must import nothing from `firebase/*`, `vault/*` or `App`.
  - Vault terms only exist after the async unseal, so they arrive later through the setter `setVaultScanner(fn)`, called by boot's `vaultScan.init()` (ARCH §15.1; an empty scanner when there is no vault). Until then any AI-host request fails closed with `NO_SCANNER` (ARCH §8.5). The scanner always covers the active vault (the fake vault in Judge Mode, R-14).
  - Whether Vite 8/Rolldown's production bundle keeps this evaluation order is U-54. Check it with an ordering `console.log` under `vite preview`.

### 2.3 Anonymous Auth

```ts
// [VERIFIED: docs; signInAnonymously behaviour VERIFIED: src auth 1.13.11. As built in firebase/init.ts (D-110, T-101)]
import { getAuth, signInAnonymously } from 'firebase/auth';
export const auth = getAuth(app);                 // after initializeAppCheck, before getAI
let signingIn: Promise<string | null> | null = null;
export function ensureAuth(): Promise<string | null> {   // the gate awaits this before EVERY cloud call
  if (auth.currentUser) return Promise.resolve(auth.currentUser.uid);
  signingIn ??= Promise.race([
    signInAnonymously(auth).then(c => c.user.uid, () => null),       // offline / provider off → null
    new Promise<null>(res => setTimeout(() => res(null), 5_000)),    // Auth's start-up awaits IndexedDB with no timeout
  ]).finally(() => { signingIn = null; });                            // the next call retries
  return signingIn;
}
export const authReady = ensureAuth();              // the first attempt only; never the gate's check
```

- `signInAnonymously` waits for the persisted state and **returns the existing anonymous user** instead of creating a new one.
- Firebase limits new anonymous sign-ups per IP.
- A rejected `signInAnonymously` (offline, provider disabled) is not retried by the SDK `[VERIFIED: src auth 1.13.11]`. A promise made once at start-up therefore stays `null` all session; the app's `ensureAuth()` (`firebase/init.ts`, D-110) retries on the next call and shares one in-flight attempt.
- **Enable the provider:** in the console (Security → Authentication → Sign-in method → Anonymous), or as code with `"auth": { "providers": { "anonymous": true } }` in `firebase.json` plus `firebase deploy --only auth` (U-17).

### 2.4 Remote Config (web)

**Key names, types and defaults are owned by ARCH §13.** Once it exists in the repo, `/remoteconfig.template.json` is the source of truth. Client defaults are **read from** that template at import time (the web imports the JSON through the `@root` alias and derives `RC_DEFAULTS`; iOS bundles the file). They are never hand-typed and never generated by a script (ARCH §13.4, AD-28). This section covers SDK behaviour only.

```ts
// [VERIFIED: docs+src remote-config 0.10.0]
import { getRemoteConfig, ensureInitialized, fetchAndActivate, getValue } from 'firebase/remote-config';
export const rc = getRemoteConfig(app);
rc.settings.minimumFetchIntervalMillis = import.meta.env.DEV ? 60_000 : 3_600_000; // default 43200000 (12 h)
rc.settings.fetchTimeoutMillis = 8_000;                                            // default 60000 (1 min!)
rc.defaultConfig = RC_DEFAULTS;   // derived from the imported /remoteconfig.template.json at import time (ARCH §13.4, AD-28)
export async function loadConfig() {
  await ensureInitialized(rc);              // loads last-ACTIVATED config from IndexedDB (works offline)
  void fetchAndActivate(rc).catch(() => { /* offline → 'remoteconfig/fetch-client-network'; keep cached/defaults */ }); // never awaited (D-109): on a lie-fi network it can take fetchTimeoutMillis
}
const v = getValue(rc, 'adversary_model'); v.asString(); v.asBoolean(); v.asNumber(); v.getSource(); // 'static'|'default'|'remote'
```

**Offline behaviour:**
- State lives in the IndexedDB database `firebase_remote_config`.
- `getValue` returns the active value, else the `defaultConfig` value, else a static empty value.
- **Reading before `ensureInitialized` resolves gives only the defaults.**
- A fetch inside `minimumFetchIntervalMillis` is served from the cache with no network call.
- Otherwise, offline, the fetch rejects with `fetch-client-network`, `lastFetchStatus` becomes `'failure'` (or `'throttle'`), and nothing is activated.

**Values:**
- All values are strings; booleans are `"true"`/`"false"`; JSON values are stringified with `valueType: JSON`.
- **Never put secrets or prompt text in Remote Config** (ARCH AD-14).
- `isSupported()` checks for IndexedDB.
- Real-time updates: `onConfigUpdate(rc, { next, error, complete })`. ARCH uses it so the kill switch applies within seconds.
  - `next` fires after the SDK has **fetched** the new template itself (a realtime fetch with `cacheMaxAgeMillis: 0`) and only when some key changed, but **nothing is activated**: the listener must call `activate(rc)` and re-read. `complete` is never called. `[VERIFIED: src remote-config 0.10.0, RealtimeHandler.fetchLatestConfig]`
  - The stream needs the Remote Config Realtime API on the project `[UNVERIFIED: whether it is on by default for strangers-eyes; if not, error fires and a flipped kill switch applies at the next start or fetch]`.
- `Value.asNumber()` is `Number(value) || 0` and `asBoolean()` is true for "1", "true", "t", "yes", "y", "on" (case-insensitive) `[VERIFIED: typings 0.10.0]`: junk silently becomes 0 or false. The app reads `asString()` only and validates it itself (`firebase/rcParse.ts`, D-108).
- `getRemoteConfig` falls back to in-memory storage when IndexedDB is unavailable and itself starts `ensureInitialized` at construction `[VERIFIED: src 0.10.0 remoteConfigFactory]`. A key with neither an activated nor a default value reads as `''` with source `'static'`; that never happens here because `defaultConfig` holds every template key.
- **No `temperature` key** (§1.11).

**As code:**
- In `firebase.json`, set `"remoteconfig": { "template": "remoteconfig.template.json" }`, then `firebase deploy --only remoteconfig`. The CLI fetches the ETag itself (U-17).
- Template parameter shape: `{"parameters":{"<key>":{"defaultValue":{"value":"…"},"valueType":"STRING"}}}`, with `valueType` one of STRING, BOOLEAN, NUMBER, JSON.
- Console path: DevOps & Engagement → Remote Config.

Sources: https://firebase.google.com/docs/remote-config/web/get-started, https://firebase.google.com/docs/remote-config/automate-rc, https://firebase.google.com/docs/reference/remote-config/rest/v1/RemoteConfig

### 3.5 HybridModel fallback semantics (why S0/S1 must never use it)

`[VERIFIED: src 12.19.3 Types/Internal/HybridModelSession.swift]`

- It falls back on **any** primary error except cancellation: unavailability, guardrail or refusal errors, tool errors, `unsupportedPromptContent`. For example, **an image part sent to the on-device model is silently re-sent to the cloud**.
- It does not fall back if the primary session already has history.
- Once it has fallen back, it stays on the secondary model.
- A stream falls back only if nothing has been yielded yet.
- It only logs a notice.
- `[CONFLICT]` The hybrid configuration doc says "Prefer cloud: fall back only when offline". The code falls back on any error; trust the code.

**Rule:** never put S0/S1 data in a HybridModel session. Run the Egress Gate's vault-string scan before **every** HybridModel call (I5). A hit reclassifies the call to S0 (D-15).

### 5.2 Tesseract.js 7 (Apache-2.0)

- **API:** `createWorker(langs='eng', oem=OEM.LSTM_ONLY (1), options?, config?)`; `worker.recognize(image, options?, output?, jobId?)`; `worker.setParameters({...})`.
- **Since v6 only `text` is returned by default.** For word boxes, pass `{ blocks: true }` as the **third** argument, then walk `data.blocks[].paragraphs[].lines[].words[]`. Each word is `{ text, confidence (0–100), bbox {x0,y0,x1,y1} (px) }`; `data.blocks` is `null` unless requested.

- The Blob-URL worker (`importScripts(workerPath)`) **worked offline** under the service worker.

- **`createWorker` can hang forever** `[VERIFIED Nov 21, T-057 review: tesseract.js 7.0.0 src/createWorker.js]`.

- **Per-job Tesseract parameters** `[VERIFIED Nov 21, same source]`. `recognize(image, { thresholding_method: '2' }, output)` passes non-tesseract.js keys to Tesseract inside `SaveParameters`/`SetVariable`…`RestoreParameters`, so the setting applies to that job only and can never leak into another. ### 5.3 EXIF strip by canvas re-encode, and the gate check

`[VERIFIED: ran in Chrome 157 with a JPEG carrying Orientation=6 and GPS]`

- `createImageBitmap(blob, { imageOrientation: 'from-image' })` returns the rotated bitmap. **`'none'` and no option ALSO rotate in Chrome 157**, so Chrome always applies EXIF orientation.
- After `toBlob('image/jpeg', q)`: **APP1 (EXIF/XMP) is gone** and `exifr.gps()` is `undefined`.
- **Chrome's canvas JPEG always contains APP0 (JFIF) and APP2 (an sRGB ICC profile, "Google Inc. 2016")**, so `exifr.parse(blob, true)` returns JFIF and ICC fields. The gate tests for APP1/APP13 and GPS, not "no metadata at all" (D-19).
- **exifr:**
  - `parse` resolves `undefined` when nothing is found; `gps()` returns `{latitude, longitude}` or undefined; `orientation()` exists; the default import works;
  - **`silentErrors` is not in its TS types** (TS2353), so omit it.
- **Working image:** longest side **≤2048 px** (SPEC D-20; this verified `reencodeClean` default). All boxes live on this one oriented image. Nano gets a 768 px copy and the cloud a 1536 px copy, at the same aspect ratio.
  - Resolved in T-022 (R-07): ARCH §11.1 and §18 use the ≤2048 px master; an earlier ARCH draft used 3072 px. Tier-0 OCR runs on a 1600 px downscale (`ocr_max_px`).
- HEIC in desktop Chrome's `createImageBitmap` probably fails (U-32). Catch the error and show "convert to JPEG".
- **Never hand exifr a whole untrusted file** `[VERIFIED Nov 20, T-053 round-5 verifier, exifr 7.1.3 source + probes]`. Its file parsers walk structure the app's sniff does not bound:
  - PNG: chunks to the end of the file, past IEND;
  - JPEG: a byte-by-byte scan through the bodies of every segment except APPn/SOF0/SOF2/DHT/DQT/DRI/COM, so an APP header hidden in such a body jumps it past the SOS;
  - HEIF: every box from meta to the end of the file.
  - A crafted 30 MB file cost about 1 s and 365–577 MB. exifr also throws on a PNG with 1–10 trailing bytes after IEND.
  - The app hands exifr only the EXIF TIFF found by its own capped walks (`sniff.exifTiff`): 0.6–1.5 KB on the 10 spike photos, against ~1 MB files.
  - exifr's TIFF parser also trusts each tag's value count: it allocates arrays of that size and strips trailing NULs one character at a time. A crafted 30 MB TIFF cost about 2.5 s, so only the first 1 MiB is handed over: about 5 ms on a crafted 1 MiB TIFF. Not 64 KiB, because Apple ImageIO writes the GPS IFD after the Exif IFD's values, past 100 KB after a large UserComment (round-6 and round-7 verifiers).

```ts
// reference src/lib/exif.ts  [VERIFIED: tsc + ran]
import exifr from 'exifr';
export async function reencodeClean(src: Blob, { maxDim = 2048, quality = 0.9 } = {}) {
  const bmp = await createImageBitmap(src, { imageOrientation: 'from-image' });
  const s = Math.min(1, maxDim / Math.max(bmp.width, bmp.height));
  const width = Math.round(bmp.width * s), height = Math.round(bmp.height * s);
  const c = document.createElement('canvas'); c.width = width; c.height = height;
  const ctx = c.getContext('2d')!; ctx.imageSmoothingQuality = 'high';
  ctx.drawImage(bmp, 0, 0, width, height); bmp.close();
  const blob = await new Promise<Blob>((res, rej) => c.toBlob(b => b ? res(b) : rej(new Error('toBlob null')), 'image/jpeg', quality));
  return { blob, width, height };
}
// Byte-level gate check: APPn markers before SOS. Clean Chrome output = ['APP0','APP2'].
export async function jpegAppSegments(blob: Blob): Promise<string[]> {
  const b = new Uint8Array(await blob.arrayBuffer()); if (b[0] !== 0xff || b[1] !== 0xd8) throw new Error('not JPEG');
  const found: string[] = []; let i = 2;
  while (i + 4 <= b.length && b[i] === 0xff) { const m = b[i + 1]; if (m === 0xda) break;
    if (m >= 0xe0 && m <= 0xef) found.push(`APP${m - 0xe0}`); i += 2 + ((b[i + 2] << 8) | b[i + 3]); }
  return found;
}
// GATE RULE: FAIL if segments include 'APP1' or 'APP13', or (await exifr.gps(blob)) !== undefined.
export const findMetadata = (blob: Blob) => exifr.parse(blob, { tiff: true, ifd1: true, exif: true, gps: true, interop: true,
  xmp: true, icc: true, iptc: true, jfif: false, ihdr: false, makerNote: true, userComment: true, mergeOutput: false });
```

### 5.4 Vault: WebCrypto AES-GCM with a non-extractable key in IndexedDB

`[VERIFIED: ran in Chrome 157; Safari/Firefox U-59]`

- `generateKey({name:'AES-GCM', length:256}, false, ['encrypt','decrypt'])` returns a CryptoKey that idb-keyval stores and reads back by structured clone, still with `extractable === false`.
- `exportKey('raw')` throws `InvalidAccessError`. The encrypt/decrypt round trip works.
- The IV must be **unique per encryption** and should be 96 bits. The tag defaults to 128 bits.
- idb-keyval `createStore(db, store)` opens the DB with no version and creates the store only on first upgrade, so use **one object store per database**.
- **Never use idb-keyval's default store**: tesseract.js owns `keyval-store`.
- ARCH §16.3 decides the layout: only the vault lives in `se-vault-data`; sessions and queue are sealed in `se-sessions`; the ledger is unsealed in `se-ledger`; settings use localStorage.

```ts
// reference src/lib/vault.ts  [VERIFIED: tsc + ran]
import { createStore, get, set, del } from 'idb-keyval';
const keyStore = createStore('se-vault-keys', 'keys');
const dataStore = createStore('se-vault-data', 'items');
export async function getVaultKey(): Promise<CryptoKey> {
  const k = await get<CryptoKey>('vault-key-v1', keyStore); if (k) return k;
  const key = await crypto.subtle.generateKey({ name: 'AES-GCM', length: 256 }, false, ['encrypt', 'decrypt']);
  await set('vault-key-v1', key, keyStore); return key;
}
interface Sealed { v: 1; iv: Uint8Array<ArrayBuffer>; ct: ArrayBuffer }
export async function putSealed(id: string, value: unknown) {
  const iv = crypto.getRandomValues(new Uint8Array(12));
  const ct = await crypto.subtle.encrypt({ name: 'AES-GCM', iv }, await getVaultKey(), new TextEncoder().encode(JSON.stringify(value)));
  await set(id, { v: 1, iv, ct } satisfies Sealed, dataStore);
}
export async function getSealed<T>(id: string): Promise<T | undefined> {
  const r = await get<Sealed>(id, dataStore); if (!r) return undefined;
  const pt = await crypto.subtle.decrypt({ name: 'AES-GCM', iv: r.iv }, await getVaultKey(), r.ct);
  return JSON.parse(new TextDecoder().decode(pt)) as T;
}
export async function burnVault() { await del('vault-key-v1', keyStore); indexedDB.deleteDatabase('se-vault-data'); } // key first (SPEC AC-271)
```

- The app's `burnVault()` (ARCH §16.4) also deletes `se-sessions` and `se-ledger` after `se-vault-data`, with no partial option (SPEC D-31; D-50). The snippet shows only the verified key-first order.
- **IndexedDB behaviours the burn relies on** (T-054 reviews, Nov 20; D-80). Verified in fake-indexeddb 6.2.8 and, where marked, in Chrome 156 (Browser pane):
  - `deleteDatabase` gets `blocked` while another connection is open and finishes only once that connection closes. A second `deleteDatabase` of the same name, queued behind a pending one, gets **no** `blocked` event, so a timer that starts on `blocked` never starts. The app times every deletion from the request instead.
  - `indexedDB.databases()` still lists a database whose deletion is blocked, and an `open()` queued behind that deletion waits until the blocker closes `[Chrome 156]`. **Never inspect with `open()` while a deletion is pending:** it re-creates the database.
  - Checking whether a database exists without creating it: `open(name)` with no version; in `onupgradeneeded` (oldVersion 0) call `req.transaction.abort()`. The open fails with `AbortError` and no database is left behind. An existing database opens; close it at once so it never blocks a later deletion `[Chrome 156]`. Used only where `databases()` is missing or throws.
  - `indexedDB.databases()` support: Chrome 71+, Safari 14+, Firefox 126+ (MDN). Safari and Firefox are unverified here (U-59).
  - `BroadcastChannel` is same-origin and stays on the device. The vault-change message carries no data.

```ts
// [VERIFIED: ran] mapping; the padding rule below is the spec rule (our composition, test with Vitest)
export type Box2D = [number, number, number, number];   // [ymin, xmin, ymax, xmax], 0..1000 of the image SENT
export function box2dToPx(box: Box2D, width: number, height: number, padPx = 0) {
  const [ymin, xmin, ymax, xmax] = box.map(v => Math.max(0, Math.min(1000, v))) as Box2D;
  const x = Math.max(0, Math.floor(Math.min(xmin, xmax) / 1000 * width) - padPx);
  const y = Math.max(0, Math.floor(Math.min(ymin, ymax) / 1000 * height) - padPx);
  const x1 = Math.min(width, Math.ceil(Math.max(xmin, xmax) / 1000 * width) + padPx);
  const y1 = Math.min(height, Math.ceil(Math.max(ymin, ymax) / 1000 * height) + padPx);
  return { x, y, w: x1 - x, h: y1 - y };
}
// Fill: ctx.save(); globalAlpha = 1; globalCompositeOperation = 'source-over'; fillStyle = '#000'; fillRect(...); restore()  — never blur/pixelate
```

## 6. Gemini prompting, boxes and grounding rules

### 6.1 `box_2d` convention

`[VERIFIED: docs]` https://aistudio.google.com/docs/image-understanding

- The format is `[ymin, xmin, ymax, xmax]`, **y first**, integers normalised to 0–1000 relative to the image as sent.
- Detection has been supported since Gemini 2.0. Google's samples state the format inside the prompt and use `gemini-4-hydrogen`.
- Gemini's boxes are approximate: **clamp, swap reversed corners, drop zero-area boxes, then pad.** Prefer OCR boxes for text.

### 6.2 Image input

See §1.8: 20 MB, downscaling above 3072², tokens, text before image, and `type` on parts.

### 6.3 Structured output with images

- Firebase supports structured responses to multimodal requests `[VERIFIED: docs]` (https://firebase.google.com/docs/ai-logic/generate-structured-output). Keyword support: §1.7.
- `responseJsonSchema` is typed `{ [key: string]: unknown }` `[VERIFIED: src]`. ARCH's `plain(schema)` helper returns `Record<string, unknown>`, which sidesteps `as const` readonly-type friction.
- U-45 `[VERIFIED Nov 20, T-031]`: `maxItems` on arrays of objects is what breaks it. The grammar unrolls each allowed repetition, and with 12/3/8 caps both gemini-3.8-flash and gemini-4-hydrogen return `400 … too many states for serving`. Without those caps (keeping `additionalProperties:false`, the enums, `required` and box_2d's 4/4) hydrogen accepts it. **Rule: never put `maxItems` on an array of objects in a cloud schema; cap in code.**

### 6.4 Two-pass adversary (decided: D-02, AD-03)

| Pass | Config | Input | Output used for |
|---|---|---|---|
| **A** (advA.v1) | ONLY_IN_CLOUD, `tools:[{googleSearch:{}}]`, streamed, thinkingLevel MEDIUM | redacted JPEG | **display only**: Markdown + Search Suggestion (shadow root, same width) + source chips. **Never** parsed by code or Nano, never cached across users, never in metrics |
| **B** (advB.v1) | ONLY_IN_CLOUD, **no tools**, `responseMimeType:'application/json'` + `responseJsonSchema`, thinkingLevel MEDIUM | the **same** redacted JPEG, **in parallel** with A; never sees A | referee, clue boxes, hypotheses, re-attack comparison, benchmark, Leak Atlas types |
| **C3 re-attack** | B again (optionally A) | the fixed image | before/after band comparison |

- **Why two passes:** the grounding **terms** (no analysing or modifying grounded results) and data isolation, not flakiness. A single grounding+schema call is documented only as Preview on the Interactions API (U-08), and its output would itself be a Grounded Result.
- **Never copy AI Studio snippets.** They now use the Interactions API (`client.interactions.create`, `response_format`, `tools:[{type:"google_search"}]`). Firebase uses `generationConfig.responseMimeType/responseSchema/responseJsonSchema` and `tools:[{ googleSearch: {} }]`.

### 6.5 Determinism plan (replaces "temperature 0"; D-01, AD-02)

- Pin an **exact** model ID in Remote Config.
- **Version every prompt** (advA.v1 …). Prompt text is bundled in `shared/prompts/`; RC only selects among bundled versions (AD-14).
- Fix the adversary's `thinkingLevel` at MEDIUM.
- Use strict ordering and ID rules in the prompts (c1, c2…, most revealing first).
- **Cache pass B per user and session**, keyed by `sha256(image) + model + promptVersion`.
  - Recorded pass-B outputs for synthetic samples may ship for Judge Mode (D-12).
  - **Pass A is never cached.**
- Benchmark with k=3 runs per photo and report the spread. The verdict uses the closest band across up to 3 hypotheses.
- Optional: a cast `seed` (U-11).
- Pre-test the exact demo photos 10× or more.

### 6.6 Refusals and policy

- **Refusal paths:**
  - pass A replies `DECLINED: <reason>`;
  - pass B returns `audit_status: "declined"`;
  - `response-error` (SAFETY, SPII…) means blocked.
  - Every one of them shows "Adversary declined; on-device findings only". **Never retry with different framing** (the terms forbid bypassing safety; D-18).
  - Transient errors (network, 5xx, 429, truncation) may be retried with the **identical** request.
- **Generative AI Prohibited Use Policy** (last modified 2024-12-17, https://policies.google.com/terms/generative-ai/use-policy):
  - forbids tracking or monitoring people without consent, using personal data or biometrics without legally required consent, harassment, and CSAE;
  - allows exceptions for educational, documentary, scientific or artistic purposes, or where public benefit outweighs harm.
- **Gemini API Additional Terms:** users must be 18+, and only paid services may serve users in the EEA, UK or Switzerland.
- **Refusal data:**
  - None is published for gemini-3.8-flash or gemini-4-* (U-13, Day-1 spike b).
  - Reference point: in VLM-GeoPrivacy (arXiv 2602.05023), Gemini 2.5 Flash rarely refused geolocation.
  - Doorstep-like hero and Judge scenes with name-tag props may behave differently from street scenes (U-61).
- **Framing:**
  - the owner commissioned an audit of their own photo;
  - scene only, never people;
  - no personal names, plates, house numbers or private-home addresses echoed back;
  - Search only for public features;
  - a clean decline path.
  - Leaving PII out also lowers the risk of SPII blocks.

### 6.7 Enums

The canonical file is `shared/prompts/enums.v1.json`; its content is in ARCH §10.3. It holds CLUE_TYPES (18), INFERENCE_KINDS, CONF, LEVELS and REGIONS. The Firestore whitelist and both platforms read it.

The Gemini `LEVELS` include `region`, while code bands (§5.6) include `none`. These are different scales on purpose: one is the model's claimed precision, the other is the measured distance to the user's own pins.

## 9. Known gotchas (most expensive first)

1. **ONLY_ON_DEVICE is not a privacy guarantee on the web.** Without `window.LanguageModel` it silently uses the cloud. Gate every S0/S1 call on a fresh `availability(sameCreateOptions) === 'available'`, never a cached one (§1.5).
2. **iOS HybridModel falls back to the cloud on any error**, image parts and guardrail errors included. Only public S2 text goes in (§3.5).
3. **iOS SDK "latest" (13.x) has no HybridModel.** Pin exactly 12.19.3 (§3.1).
4. **Init order:** `initializeAppCheck` and `getAuth` must run before the first `getAI()`, or AI calls carry no tokens and enforced App Check rejects them (§1.2).
5. **App Check is already enforced for AI Logic** (since 2026-11-02). Localhost fails until the [USER] registers the debug token. A `true`-flag token is per browser profile and changes when site data is cleared.
6. **Debug token in `.env.local` reaches `vite build`.** Use `.env.development.local`, and grep `dist` for the token **value** (§1.2).
7. **ESM hoists imports.** Install the fetch tripwire from a side-effect module imported first; pass `data:` URLs through untouched (§1.17).
8. **Hybrid mode silently drops top-level `model`, `tools`, `generationConfig` and `systemInstruction`.** Put them under `inCloudParams`.
9. **The device path ignores `systemInstruction`, `generationConfig` and `tools`.** Instructions go in the user turn, the schema in `responseConstraint`. PREFER_ON_DEVICE with tools runs on Nano without the tools.
10. **Every part literal needs `type`** in v13, or the TS build fails.
11. **"Temperature 0" does nothing** on Gemini 3.x+. presence/frequencyPenalty → 400. MINIMAL thinking → 400 on 3.8-flash and 4.x; `thinkingBudget` → 400 on 4.x.
12. **Grounding needs Blaze (paid tier).**
    - Render `renderedContent` unmodified in a shadow root, at the same width, always visible, with sources.
    - Capture `groundingMetadata` **per stream chunk**.
    - Never cache pass A across users, and never feed it to pass B, the referee, Firestore or metrics.
13. **`response.text()` throws on SAFETY/SPII and similar, but MAX_TOKENS returns truncated JSON.** A parse failure is a failure. Never re-prompt after a refusal.
14. **One face threshold (0.3) for Tier-0 and the gate**, and the gate's OCR runs on the exact outgoing bytes in the consent dry run (§5.1, §5.2).
15. **Re-encode to JPEG before every AI call.** webp/heic fall back to the cloud in PREFER mode; the device accepts only jpeg/png.
16. **Chrome's canvas JPEG keeps APP0 + APP2.** Gate on APP1/APP13 + GPS.
17. **Chrome applies EXIF orientation** even with `imageOrientation:'none'`. Compute every box on the one ≤2048 px working image you mask and send. Never letterbox.
18. **`initializeDeviceModel()` needs a user gesture.** Until the download finishes, PREFER mode quietly uses the cloud.
19. **`AbortSignal`/`timeout` don't cancel device inference**, and aborting doesn't stop cloud billing. `countTokens` and chat don't work on the device; every device call is a fresh session.
20. **On-device limits:** Nano input ≤9,216 tokens; iOS FM ≤4,096 tokens (the Simulator reports `contextSize` 0); iOS FM runs in the foreground only.
21. **iOS Simulator:** FM tool calling and image Attachments fail despite the capability flags; Vision faces need the **CPU compute device**; FM takes 18–30 s per call.
22. **iOS metadata:** `CGImageDestinationCopyImageSource` leaves GPS in HEIC/PNG. Re-encode the pixels, and bake orientation first.
23. **iOS debug token via `simctl launch`:** use `SIMCTL_CHILD_AppCheckDebugToken`; scheme env vars only apply to Xcode runs (§3.3).
24. **8 GB RAM:** never run Chrome Nano and Simulator FM together. Chrome's documented floor (16 GB RAM, or >4 GB VRAM) may or may not pass.
25. **Emulators:** firebase-tools 15.37 needs Java 21. Use `npx firebase-tools@13.35.1` with a dedicated minimal `firebase.json`.
26. **vite-plugin-pwa fails the build on files over 2 MiB.** Set `maximumFileSizeToCacheInBytes`. Setting `globPatterns` replaces the defaults.
27. **Tesseract:** rejects ImageBitmap; needs `{ blocks: true }` as the **third** `recognize` argument; `corePath` is a directory (self-host all three LSTM cores); owns idb-keyval's default store.
28. **MediaPipe:** CPU delegate, full-range model, self-hosted wasm path with no trailing slash. The `console.error` XNNPACK line is harmless.
29. **Remote Config:** call `ensureInitialized` before reading; default fetch timeout 60 s (set 8 s), default interval 12 h; values are strings; key names come from ARCH §13 only.
30. **Firestore:** call `initializeFirestore` once (HMR); never await writes offline; the whitelist must equal `CLUE_TYPES`; counted content is governed by SPEC D-11.
31. **Free-tier data is used for training**, EEA/UK/CH users need the paid tier, and users must be 18+.
32. **Search-grounding billing** is per query: 5,000 free a month, 1,500/day default cap.
33. **Per-user AI Logic RPM below ~30** will 429 Judge Mode bursts and the benchmark (§1.14).
34. **`gemini-3.6-flash` shuts down today** (Agent Platform) and `gemini-2.5-*` is rerouted or gone. Use 3.8-flash or 4-hydrogen from RC.
35. **iOS 12.19.3 `responseJSONSchema` init is internal.** Use `GenerationConfig(…responseMIMEType:responseSchema:…)`.
36. **iOS name clash:** always write `FirebaseAI.SystemLanguageModel.default` when FoundationModels is also imported.
37. **Gemini `box_2d` is y-first**, 0–1000, approximate. Clamp, swap, pad 15%, and prefer OCR boxes for text.
38. **Don't copy AI Studio snippets** (Interactions API syntax), and don't follow the iOS docs' `serverTools`/`GeminiTool` (compile errors).
39. **`vite preview` on localhost has no debug token.** Test production builds on a Hosting preview channel and add that domain to the reCAPTCHA key.
40. **`firebase init aitools` edits CLAUDE.md.** Avoid it.
41. **A strict CSP may break grounding `renderedContent`.** Don't send COEP `require-corp`.
